# 공고 일정 추출 실측 (2026-11-18)

`extract/schedule.py`(설계서 v0.17)를 기관 누리집에 공개된 실제 입찰공고문·제안요청서로 돌려 본 기록입니다.
원문 파일은 저장소에 넣지 않았고, 테스트에는 일정 문구와 표 모양만 옮겼습니다(`tests/test_schedule.py::test_real_notice_phrasings`).

## 처음 결과와 고친 것

| 문제 | 문서 | 고친 것 |
|---|---|---|
| '입찰 관련 서류(제안서 포함) 제출 마감 일시'를 일정으로 못 봄 | 2·3 | '입찰·참가·제안 … 서류 … 제출 마감/기한/일시'를 제안서 제출로 |
| '가. 제출 마감 일시'에서 '가.' 때문에 이름표를 못 봄 | 4 | 이름표 앞 기호·번호(가., 1), ①, ❍)를 떼고 본다 |
| '(금), 11:00'의 시각을 놓침 | 4·6 | 날짜와 시각 사이 쉼표 허용 |
| 한 행의 두 번째 '이름표 \| 날짜' 쌍을 못 봄, '입찰서(가격)마감일시'의 괄호 | 1 | 표 행의 날짜 칸마다 바로 왼쪽 칸(없으면 열 머리글)을 이름표로, 괄호 안을 뺀 글자로도 종류를 고름 |
| '③ 제안서 설명 및 평가'를 평가 일정으로 못 봄 | 8 | 동그라미 숫자를 떼고, '제안서 설명 및 평가'를 평가로 |
| 법령 인용 날짜를 평가 일정으로 오인('제안서 기술평가는 … 고시(제2021-3호, 2021.1.19.)한 …') | 9 | 날짜 앞에 고시·예규·지침·법률·'제N호'가 있으면 일정이 아님, 본문 줄은 '이름표:' 꼴이나 짧은 이름표만 |

## 고친 뒤

- 일정이 있는 7건: 제출 마감 7/7, 시각 7/7, 기간(개시~마감) 2/2, 평가 일정 1/1을 맞게 읽었습니다.
- 일정이 없는 2건과 공개 RFP 2건: 잘못 고른 일정 0건, 제출 마감을 못 찾았다는 안내(NOTICE-DEADLINE)만 남깁니다.
- 질의 기간·제안요청 설명회가 적힌 실제 공고는 이번 표본에 없었습니다. 이 둘은 체험용 예제와 단위 테스트 문구로만 확인했습니다.
